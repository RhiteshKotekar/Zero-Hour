# 2. IMMEDIATE PRIORITY: FIX THE EXPERIMENT JSON ISSUE

This is your first implementation task.

## Known issue

The current repository has an inconsistency between the experiment output format and the dashboard's expected input format.

The previously identified problem is:

- `scripts/run_experiment_a.py` writes `experiment_a.json` using `summary_json(result)`.
- `src/samg/dashboard/data.py` attempts to load that file using `ExperimentResult.model_validate_json(...)`.
- The summary JSON does not contain the complete `ExperimentResult` fields, including `training_rewards` and `records`, and includes summary-specific fields such as `table`.

As a result, the Adaptive Evaluation Lab cannot reliably load the experiment output generated by the experiment script.

You MUST independently inspect the current implementation and reproduce this issue before fixing it.

Do not blindly assume the previous diagnosis is still accurate.

## Desired outcome

The experiment runner and dashboard must agree on a well-defined serialization contract.

I want the following behaviour:

1. The experiment runner can save a complete, reproducible experiment result.
2. The dashboard can load and validate that complete result.
3. The dashboard can display policy comparisons, confidence intervals, regret and learning curves.
4. The existing human-readable summary output must remain available.
5. Existing experiment artifacts must not be silently overwritten or corrupted.
6. Missing, malformed or incompatible JSON artifacts must produce understandable errors rather than crashing the dashboard.
7. My teammates must be able to run an experiment and immediately inspect its results in the dashboard.

## Recommended implementation direction

Inspect the existing `ExperimentResult` model and serialization helpers.

Prefer maintaining two distinct artifact formats:

**A. Full machine-readable experiment artifact**

For example:

`artifacts/experiments/experiment_a.json`

This should contain the complete serializable experiment result.

Use the appropriate Pydantic serialization method, such as:

`result.model_dump_json(indent=2)`

Do not use a summary-only serializer for an artifact that is expected to reconstruct the complete model.

**B. Human-readable summary artifact**

For example:

`artifacts/experiments/experiment_a_summary.json`

This can continue using `summary_json(result)` or the existing reporting helper.

However, inspect the repository's existing conventions before deciding filenames or formats. Preserve established paths wherever possible.

## Backward compatibility

Inspect existing experiment artifacts and determine whether any are already consumed elsewhere.

Do not break:

- CLI output.
- Existing experiment reporting.
- Experiment reproducibility.
- The security experiment.
- Existing dashboard data contracts.

If legacy summary JSON files exist at the expected full-artifact path, handle them gracefully.

Do not silently interpret a summary as a full experiment result.

Display a clear message explaining which artifact is missing or incompatible and how to regenerate it.

## Tests you MUST implement

Add tests for:

1. Full `ExperimentResult` serialization and deserialization round-trip.
2. Experiment runner producing the full artifact.
3. Summary artifact still being generated.
4. Dashboard loading the full artifact successfully.
5. Dashboard rendering when the full artifact is missing.
6. Dashboard handling malformed JSON.
7. Dashboard handling legacy summary-only JSON.
8. Dashboard displaying correct learning-curve data.
9. Dashboard displaying correct experiment comparison data.

Use temporary directories for tests wherever possible.

Do not make tests dependent on previously generated experiment files in the repository.

Do not fabricate experiment results to satisfy the dashboard tests.

## Acceptance criteria

The issue is considered fixed only when all the following are true:

- Running the experiment script produces the expected full JSON artifact.
- The full JSON can be parsed back into the original `ExperimentResult`.
- The summary JSON is still generated.
- The dashboard successfully loads the full artifact.
- All relevant dashboard tests pass.
- Existing experiment tests pass.
- The dashboard does not crash when an artifact is absent or invalid.
- A teammate can reproduce the workflow from the documentation.

## Test the actual workflow

After fixing the issue, execute:

1. Generate an experiment using the existing experiment runner.
2. Confirm both output artifacts exist.
3. Validate the full artifact by deserializing it.
4. Start the Streamlit dashboard.
5. Navigate to Adaptive Evaluation Lab.
6. Verify that the experiment results appear.
7. Verify the learning curve.

If browser interaction is unavailable, use Streamlit AppTest or another automated rendering check, and clearly distinguish this from manual browser acceptance.

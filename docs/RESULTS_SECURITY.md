## Trust boundary and limitations

- **The witness is trusted.** It signs simulator task transitions faithfully; the ACP-recomputed reward equals ground truth because the witness is faithful (D033). A compromised or colluding witness is out of scope, as is theft of the witness or coordinator private key.
- The attacker is one authorised agent using its own real key with fresh sequence numbers. Authentication, authorisation and freshness therefore all pass; only witness corroboration stops the claim. Colluding agents and Byzantine behaviour beyond false reports are not tested.
- The protected learner never uses a claimed reward, so the S2 result is partly by construction; what the run measures is that this holds end to end (persistence, gate, learning events) and what it costs (FRR, PROVISIONAL episodes when evidence is missing).
- FRR is measured under a faithful, noise-free witness and integer-millisecond timing, so a 0 FRR is expected; it says nothing about FRR with a lossy or noisy witness (only the withheld-witness case is tested, and there the protected learner stops learning).
- The compromised agent files false completion claims only for its own tasks that really failed; with no sabotage in this run, the unsupported reports are the type counts listed per level.
- Follow-up evaluation uses frozen copies (no learning on follow-up missions), so it measures the poisoned state's decisions, not recovery. Sample sizes are small and shown with every rate.
- The vulnerable learner's harm is bounded by the reward range [0, 1] and the bandit's ridge prior; a larger corruption level or magnitude would move it more. Corruption levels are configuration, not rates.
